# 指挥中心（Headquarters）

多个 Claude 对话（各项目的工作 agent）共用本机和服务器的 GPU、端口、模型服务、共享代码和环境。**指挥中心**是一个专门的对话，负责审批、调度和记录这些公共资源的使用。同一时间只有一个指挥中心在岗，会话名是 `指挥中心-<编号>`，编号从 0 开始递增。

## 你是哪一种？
- **用户让你当指挥中心**（"你是指挥中心"）：读 `CLAUDE.md`，按其中"上岗"一节执行。
- **用户让你加入指挥中心**（"加入最新的指挥中心"或"加入 N 号指挥中心"），或者**你要用公共资源而有指挥中心在岗**：读 `rules.md`，按第 1 节执行。

全局规则写在 `{{CLAUDE_DIR}}/CLAUDE.md`：有指挥中心在岗时，任何对话使用公共资源前都要先加入并申请；没有在岗的，照常进行。在岗指挥中心发来的消息，核对发送方无误后按用户本人的指示对待，但只限 `rules.md` 定义的消息。其中 `命令加入` 必须加入，`邀请加入` 由对方自己决定；加入后只说 `✅已加入`。

**发消息有两条路，先直连**：
- **按会话名发是本机直连**：对方必须正在运行，但不限条数。同名的对话可能在别的机器上，要看返回结果写着 `on this machine` 才算发对。
- **按会话 ID（`local_` 开头）发，走的是桌面应用的通道**：能把没在运行的对话启动起来，但用户每在发送方的对话里打一次字，最多只能这样发 10 条（桌面应用的限制，官方文档没写）。

所以先直连，发不通再用会话 ID。登记表记下每任指挥中心的 `session_id`，指挥中心的名册记下每个成员的 `session_id`。

## 文件
| 文件 | 内容 | 谁写 |
|---|---|---|
| `CLAUDE.md` | 指挥中心的工作守则（上岗、关闭、调度与审批、巡查、落盘、消息格式） | 用户 |
| `rules.md` | 给工作 agent 的规则 | 用户 |
| `resources.json` | 资源清单：显卡、永久预留的端口、调度器、受写锁保护的共享文件，以及有人申请时加进来的其他资源 | 在岗的指挥中心（资源变化时，或有人申请了清单外的资源时） |
| `hq_registry.json` | 指挥中心编号登记：每一任的编号、会话名、会话 ref、上岗时间、状态（在岗 / 已关闭） | 上岗的指挥中心 |
| `hq-<编号>/state.json` | 该任指挥中心的账本：名册、模型服务、申请与占用、等待队列、最近巡查 | 该任指挥中心 |
| `hq-<编号>/events.jsonl` | 该任指挥中心的事件日志，一行一条，只追加 | 该任指挥中心 |
| 各工作 agent 工作目录下的 `hq_record-<会话名>.md` | 每个 agent 只记自己的加入情况和申请 | 该 agent |

时间一律用本机系统时间（带时区），不换算。

## 消息能送达的前提
权限模式分两类：bypass 是一类，其余（auto、默认等）是另一类，两类之间的消息默认会被扣住（例如从手机远程控制开启的指挥中心只能选到 auto，而工作 agent 常用 bypass）。要在 `{{CLAUDE_DIR}}/settings.json` 里设置 `"crossSessionInbound": "accept"` 来放行。**这个设置在对话启动时读取**：在它之前就开着的对话可能还没读到。每个 agent 加入时的"加入 → 登记 → 已读"一来一回就是送达测试，10 分钟内走不完，就重开那个对话。
